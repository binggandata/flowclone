## 4. 接入层：怎么把手机"接进"Agent

### 4.1 现实路径（本项目的做法）
1. 用户在手机打开"USB 调试"并允许调试授权 → `adb devices` 出现 `d0673a58`。
2. 所有设备操作都通过 **ADB shell 接口**，由 Agent 的 `bash` 工具执行：
   - `adb shell screencap -p` → PNG 截图（视觉证据）
   - `adb shell uiautomator dump` + `adb exec-out cat` → XML 语义树（结构证据）
   - `adb shell input tap/swipe/text/keyevent` → 点击/滑动/输入/返回
   - `adb shell am start/force-stop`、`logcat`、`dumpsys window`、`svc wifi/data`
   - `adb reverse tcp:8081 tcp:8081`（手机访问本机自建 Server）
3. 把高频操作封装成脚本：`tools/ui.py`（解析 XML、按文本/描述点击、打印可点击控件）、`tools/cap.sh`（截图命名归档）。
4. 设备状态不稳时（MIUI 助手/搜索被误触、键盘遮挡、坐标漂移），每步都重新 dump 后再点，不盲点复用旧坐标。

### 4.2 为什么没用 mobile-mcp / Maestro
- 本次 DSH 会话**没有挂载 MCP 工具**，且用户约束是"先跑通、别装一堆依赖"；
- ADB + uiautomator 是更底层的稳定通道，行为可解释、可脚本化、无额外服务；
- 复盘结论：**mobile-mcp 会更省事，但 ADB 直连胜在可控与可复现**；skill 中把两者都列为接入选项。

### 4.3 关键接口清单
| 接口 | 用途 | 备注 |
|---|---|---|
| `uiautomator dump` | 页面结构、文本、坐标、可点击性 | 首选；截图只作补充 |
| `screencap` | 视觉/颜色/布局证据 | 每步一图，命名带序号+页面+状态 |
| `input tap/swipe/text/keyevent` | 操作 | 输入中文/符号用 `input text` 有限制，必要时换 ASCII 或分段 |
| `NGSFlow Gateway` | 生成能力 | `/v1/files` → `/v1/generations`（Idempotency-Key）→ `/v1/jobs/{id}` 轮询 → `/v1/jobs/{id}/outputs/{i}/content` |
| 自建 BFF Server | App 专属后端 | `/v1/auth/*`、`/v1/generations`、`/v1/jobs*`、`/v1/notifications`、`/v1/agent/chat`、`/admin/*` |

## 5. 探索层：怎么做"App 解析"

> **没有反编译**。所有信息来自公开可见的界面与用户操作结果，属于净室（clean-room）。

### 5.1 核心方法
1. **UI 语义树优先**：`uiautomator dump` 得到节点 class/text/content-desc/bounds/clickable，先建立"可点击元素图"再决定点哪里。
2. **截图补充**：语义树拿不到颜色/字号/圆角/图片；截图用于采样设计 token（黑底、#2C2D30 面板、#FF5722 强调色、圆角约 20–28dp 等）。
3. **分层遍历（3–5 层）**：首页 → 模板/项目 → 素材详情 → 编辑/延长/动画 → 高级设置，每一层都记录：入口、页面、元素、状态、返回路径。
4. **状态矩阵**：正常态/空态/加载态/失败态/选中态/多版本态/键盘弹出态/权限弹窗态；同屏不同状态各留证据。
5. **操作前后对比**：每次点击前 dump 一次、点击后 dump 一次，比较差异（新页面/新控件/文案/数值），作为"状态变化记录"。
6. **行为级观察**：不只记录界面，还记录产物效果——生成后视频时长、是否新增素材卡、版本数、通知文案、扣点、失败恢复。

### 5.2 解析难点与对策
| 难点 | 现象 | 对策 |
|---|---|---|
| Compose 语义树信息少 | 卡片节点没有 text/desc，只有 bounds | 结合截图定位，按坐标+邻接文本推断；必要时点开详情验证 |
| 坐标漂移 | 同屏两次 dump 坐标不同、键盘/状态栏变化 | **每次操作前重新 dump**；不缓存旧坐标 |
| MIUI 干扰 | 误触小爱/全局搜索/通知栏 | 点击前确认前台应用；用 `mCurrentFocus` 校验 |
| 动态内容 | 生成进度/动画/加载态不可预测 | 定时采样、记录百分比/文案变化轨迹 |
| 中文输入受限 | `adb input text` 对中文支持差 | 用英文提示词或分段/剪贴板方案 |
| 原版账号/地区 | 国行机 + PRO 账号；无 GMS 则无法登录 | 先用已登录账号；不折腾账号配置（用户允许范围） |

### 5.3 为什么不反编译（以及 REA 的问题）
- 任务一开始就明确"净室复刻、不反编译、不搬代码素材"；
- REA 的 Android 路线基于 JADX/Apktool 反编译，**与净室约束冲突**，本项目未安装/未使用（会话中无 jadx/apktool/frida/MCP 调用记录）；
- 若对象是**自己的 App / 获得授权**的 App，REA + jadx-mcp 能大幅加速 Interface/数据模型推导——skill 把这条列为"可选深度模式"，并写明授权前提。

## 6. 规格层：把"看见"变成"可施工"

产物：
1. **页面清单 + 导航图**（`spec/ui-spec-v0.md`）
2. **设计 token**：背景、面板、文字、次要文字、强调色、圆角、间距、按钮高度、字号
3. **逐屏 UI 差异表**（`spec/ui-diff-table.md`）：屏幕、元素、原版值、原生值、优先级（P0/P1/P2）、证据编号
4. **行为/状态规格**：生成中、失败、取消、多版本、通知、点数不足、断网恢复
5. **效果级对比表**（`spec/behavior-audit.md`）：延长是否变长、编辑是版本还是新素材、多份生成几张卡、计费规则、通知规则
6. **验收标准**：每屏至少正常态+空态/失败态之一；核心链路必须走真机 + 真网关；截图命名可追溯

### 6.1 复刻深度定级（本项目实际达成）
| 级别 | 定义 | 本项目 |
|---|---|---|
| L0 | 静态截图拼装/假数据 | 阶段一早期（已弃） |
| L1 | 界面布局还原（可看） | ✅ 基本完成 |
| L2 | 交互可用（可点、可导航、可输入） | ✅ 完成 |

| L4 | 状态与边界一致（失败/取消/恢复/多版本/权限/并发） | 🟡 大部分覆盖（取消受限、恢复已做） |

## 7. 重建层：App + Server 的架构

### 7.1 App（原生 Kotlin / Jetpack Compose）
- 单 Activity + Compose；9 个 Kotlin 文件、约 5,100 行
- 状态机：`Screen`（Home/Project/Asset/Set…）+ `ComposerUi` + 生成任务 `FlowAsset`
- 数据：`Repo` 内存模型 + JSON 持久化（项目/素材/版本/通知）
- 生成：`Gateway`（OkHttp/HttpURLConnection）异步 **submit → jobId → poll → download**；进程被杀后按 `jobId` 恢复
- 版本模型：编辑/延长追加 `versions`，原片保留；右侧版本指示条 + 循环滑动
- 视频：Media3 ExoPlayer 播放；延长使用 **Media3 Transformer 统一缩放重编码拼接**（解决网关分段分辨率不同导致后 8 秒不可解码）
- 安全：网关 Key 只在服务端；App 只连自建 Server（Bearer token + refresh）

### 7.2 Server（Python stdlib）
- `ThreadingHTTPServer + sqlite3`，743 行，无第三方依赖
- 账号：注册/登录（PBKDF2）、access/refresh、游客设备账号、注销级联删除
- 额度：账本流水；图片 0 点、视频按分辨率/秒计费
- 任务：代理网关异步任务、SQLite 持久化、状态轮询、输出本地缓存（网关内容下载慢）
- 通知：仅视频任务；任务完成写入通知表
- Agent：`/v1/agent/chat` 代理网关文本模型（Grok 系）→ 真实 LLM 回复（Key 不落端）
- Admin：只读用户/任务/账本/统计

### 7.3 对外接口（自建 BFF）
`/health`、`/v1/auth/{device,register,login,refresh,logout,me}`、`/v1/me`、`/v1/files`、`/v1/generations`、`/v1/jobs`、`/v1/jobs/{id}`、`/v1/jobs/{id}/outputs/{i}/content`、`/v1/jobs/{id}/cancel`、`/v1/notifications`、`/v1/push/register`、`/v1/agent/chat`、`DELETE /v1/account`、`/admin/*`

## 8. 对比验收层：怎么证明"跟原版一样"

1. **逐屏并排对比**：同一真机、同分辨率；原版左、复刻右；16 组精选（`evidence/compare-best/`）+ PDF。
2. **同流程状态对比**：同一操作序列（点哪→出现什么→返回哪里），记录每一步前后状态。
3. **效果级测试**（比 UI 更关键）：
   - 延长 8s：原版 8→16s；复刻拼接后 16s 且**整段可播放**（连续抽帧验证）
   - 编辑归属：原版同素材 2/2 版本、卡片"N 项"；复刻一致、原片保留
   - 多份生成：N 张独立素材卡；复刻一致
   - 计费：图片 0 点；视频 720p 3 点/秒、480p 1 点/秒；复刻对齐
   - 通知：仅视频生成/编辑/延长有通知；复刻对齐
   - 失败/恢复：⚠ 卡片、重试、中断续查（复刻实现）
4. **差异清单 → 修复 → 回归**：每轮留证据，直到验收通过或明确记录"已知限制"。

## 10. 踩坑与教训（真实发生过的）

| # | 症状 | 根因 | 修复/对策 | 教训 |
|---|---|---|---|---|
| 1 | 右滑直接退出 App | 无返回拦截链 | BackHandler 分层：弹层→设置→项目→首页→退出 | 手势/返回键要与原版逐层验证 |
| 2 | 生成中退出，回来显示失败 | 生成是前台协程，进程死则丢 | 拆 submit/jobId/poll/download，jobId 持久化 + 启动续查 | 长任务必须服务端化/可恢复 |
| 3 | 延长 8 秒后视频仍 8 秒 | 只把片段当版本，没拼接 | MediaMuxer/Transformer 拼接为 16s | "功能有"≠"效果对" |
| 4 | 延长后前 8 秒正常、后 8 秒花屏 | 网关分段分辨率不同（416×752 vs 400×736），MediaMuxer 单轨直接写 | **Media3 Transformer 统一缩放重编码** | 跨段拼接必须先统一编码参数 |
| 5 | 编辑后"原图消失" | 从素材详情发送时项目解析回退到第一个项目，页面跳错 | 按 当前项目→素材所属项目→ref→attach 解析 | 页面跳转错误会让用户误以为数据丢失 |
| 6 | 视频修改失败 | 上传接口 401 不刷新 + 网关内容下载极慢（4MB 2–4 分钟）+ 202 被当成功把 JSON 存成 mp4 + Android 11 不支持的 readNBytes 崩溃 | upload refresh、输出缓存、仅 200/201 成功、媒体头校验、客户端重试 10 分钟 | 下载链路要按"不可靠网络"设计 |
| 7 | 480p 被扣 24 点 | App 提交 quality 参数写死 720p | quality 映射修正 | 计费参数必须端到端核对 |
| 8 | 匿名游客生成失败 | 余额不足 + 无明确提示 | 发送前点数预检 + 402 友好文案 | 失败要给可行动原因 |
| 9 | 通知重复/过多 | 本地+服务端双写、图片也通知 | 单列表去重、仅视频通知 | 与原版规则逐条核对 |
| 10 | 环境装不上（JDK/SDK/Gradle） | Mac 无 brew、下载慢 | 手工安装 toolchain、Aliyun 镜像、后台任务 | 环境准备要单独成阶段、留脚本 |
| 11 | 设备操作总点错 | 坐标漂移/系统弹窗/键盘 | 每步 dump、按文本点击、校验前台 | 不要复用旧坐标 |
| 12 | 生成内容不可控 | 网关偶发慢/风控/模型维度不固定 | 缓存、重试、失败兜底、记录网关限制 | 外部依赖要有降级策略 |

## 12. 局限与下一步

**局限**

- 原版 Flow 的部分私有能力（模型 Nano Banana/Omni、账号风控、地区限制）无法 1:1 复刻，只能做"同交互 + 自有网关"

- 本地数据未按账号隔离；商业化缺支付、FCM 真机推送、HTTPS 部署、邮件服务
- 本次未使用 REA/反编译，因此内部实现（算法、缓存策略等）只能从行为和接口推断
