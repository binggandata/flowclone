# 商业化差距分析（复刻 App vs 原版 Google Flow）

> 结论：当前复刻是"单机客户端 + 直连 AI 网关"的可运行原型，功能链路已基本对齐；要做成商业化 App，缺的不是 UI，而是**服务端**与**运营体系**。

## 一、原版具备、我们缺失的能力

| # | 能力域 | 原版（Google Flow） | 当前复刻状态 | 商业化必需 | 建议落地 |
|---|---|---|---|---|---|
| 1 | 账号体系 | Google 账号登录、PRO/订阅、跨设备 | 无账号（本机 SharedPreferences） | ✅ | 自建 OAuth/JWT + 用户表；或接 Firebase Auth |
| 2 | 生成任务服务端队列 | 云端排队，关 App 也继续，多任务并发/配额 | 本轮已把任务交给网关异步执行 + 客户端断点恢复；但任务记录只在手机本地 | ✅ | 自建任务服务：提交→持久队列→回调/轮询→对象存储 |
| 3 | 结果存储与分发 | 云端存储 + CDN + 多端同步 | 全部存手机内部存储 | ✅ | S3/OSS 对象存储 + CDN 签名 URL |
| 4 | 计费/订阅 | Google Play IAP + AI 点数消耗 | 展示 0 点，不扣费 | ✅（收入） | Play Billing + 服务端账本（充值/扣费/退款/对账） |
| 5 | 模型路由 | Nano Banana / Veo / Omni 动态切换、降级 | 固定 Grok 两个模型直连 | ✅ | 服务端模型注册表 + 路由/降级/配额/成本核算 |
| 6 | 内容安全/审核 | 输入输出审核、举报处置、违规封禁 | 无 | ✅（合规） | 审核 API（文本+图像）+ 举报工单 + 人审后台 |
| 7 | 推送通知 | 生成完成推送 | 无（需回 App 查看） | 高 | FCM/APNs + 服务端事件 |
| 8 | 版权/水印/合规 | 可见水印开关、数据删除、隐私合规 | 无 | ✅ | 水印渲染、数据导出/删除 API、隐私政策 |
| 9 | 运营后台 | 用户/内容/任务/账单管理、灰度 | 无 | ✅ | 管理后台（用户、任务、成本、封禁、模型配置） |
| 10 | 监控告警/分析 | 崩溃、留存、转化、生成成功率 | logcat 而已 | ✅ | 埋点 SDK + 服务端指标 + 告警（任务失败率/时延/成本） |
| 11 | 多端/协作 | Web/手机、集合与分享 | 单机 | 中 | 账号云同步 + 分享链接 |
| 12 | 弹性与 SLA | 全球多区、限流、重试 | 单网关直连，无重试队列 | 高 | 服务端限流/熔断/重试/降级 + 多实例部署 |
| 13 | 应用分发 | Play 商店签名、版本灰度 | 仅 debug APK | ✅ | release 签名、AAB、内测轨/灰度、Crashlytics |
| 14 | 成本控制 | 配额、模型成本核算、点数定价 | 无（直接烧网关额度） | ✅ | 按用户/任务记账 + 预算告警 + 模型成本表 |

## 二、本轮已完成的"服务端相关"改进
1. **异步任务模型**：客户端不再"页面守着生成"——提交后立刻持久化 `jobId`，退出/被杀后重启自动恢复轮询（网关就是服务端队列，任务在云端继续）
2. **任务状态机**：GENERATING 仅在有关联 jobId 时保留，否则标记 FAILED，避免假进度
3. **失败可重试**：网关错误统一落为失败态，支持重试

## 三、建议的自建服务端（FlowClone Server）最小架构
```
App ⇄ API Gateway(HTTPS/JWT)
        ├── Auth/User 服务        （登录、订阅、额度）
        ├── Job 服务              （提交/队列/回调/配额）──▶ NGSFlow Gateway（模型）
        ├── 资产服务              （对象存储 + CDN 签名 URL）
        ├── 计费服务              （Play Billing 校验、点数账本）
        ├── 审核服务              （文本/图像审核、举报工单）
        ├── 推送服务              （FCM/APNs）
        └── 运营后台              （用户/任务/成本/封禁/灰度）
基础设施：PostgreSQL + Redis(队列) + 对象存储 + 监控(Prometheus/Sentry)
```
## 四、商业化落地顺序（建议）
1. P0：账号 + Job 服务（App 改走自建 API，网关密钥只放服务端）
2. P0：对象存储 + 推送（生成完成通知、跨设备可见）
3. P1：计费/订阅 + 点数账本 + 成本监控
4. P1：审核与举报 + 合规（水印/删除）
5. P2：运营后台、灰度、多端
